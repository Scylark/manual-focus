James and Hannah talk through Google's pre-announcement on 24 November 2026 of
its December 2026 core update, aimed at longer and more complex questions and
personalised results, and the first under a notice policy Google ties to the
CMA's fair ranking conduct requirement. They cover the new Search ranking hub,
why the Search Console feedback route isn't an appeal, what Google's new
attribution page means for AI Overview citations, and hand two jobs to AI, a
pre-update baseline and an audit of complex-question pages, plus a watch on
the dashboard feed.

## Get AI on this

Paste these into whichever AI assistant you use. Swap the bracketed parts for
your own details. The first two need file uploads, and the third needs an
assistant that can browse and run on a schedule.

### 1. Take a baseline before the December core update

```text
I run SEO for [brand], [one line on what the site does], in [market].

Google pre-announced its December 2026 core update on 24 November 2026 and
hasn't given a start date. The November 2026 core update has finished. I want
a baseline now so I can compare after the December update ends.

Attached are:
- a Google Search Console performance export by page for the last 28 days,
  with clicks, impressions, CTR and average position
- the Search Console generative AI performance report for the same period,
  if we have it

Group every page by type using its URL pattern (for example product,
category, guide, blog, support). If the pattern is unclear, put the page in
"other" and list the patterns you couldn't classify.

Give me a table with the columns: Page type | Pages | Clicks | Impressions |
CTR | Avg position | Generative AI impressions (or "not in export").

Then list the 20 pages with the most clicks, with the same columns, so I can
check them one by one after the update. Say plainly where the data is
incomplete and don't predict how the update will affect us.
```

### 2. Audit the pages that answer complex questions

```text
I run content for [brand] in [market]. Google says its December 2026 core
update improves how it ranks content for longer and more complex questions.
Google's guidance also says to avoid changing a page's date unless the content
has substantially changed.

Attached is a list of our pages that answer long or multi-part questions, with
URL, title, the question each one answers, the date shown on the page and the
date of the last substantial content change (from our CMS history, if
included).

For each page, check:
1. whether the shown date is later than the last substantial change
2. whether the main claims link to a source
3. whether a named author is shown

Give me a table with the columns: URL | Question answered | Shown date | Last
substantial change | Date-only refresh? (yes/no/unknown) | Claims sourced
(yes/partly/no) | Named author (yes/no) | Priority.

Rank by priority, with pages that fail two or more checks first. If you can't
open a page or a column is missing, say so instead of guessing.
```

### 3. Watch the dashboard for the rollout start

```text
Set this up as a routine that runs every weekday morning until the December
2026 core update has finished rolling out.

Check the Google Search Status Dashboard and its feed for ranking incidents.
Tell me, in three lines or fewer:
- whether the December 2026 core update has started, finished or is still
  only pre-announced
- the start or completion date Google gives, quoted exactly
- any new ranking incident or pre-announcement since the last check

If you can't reach the dashboard, say so. Don't infer a rollout from
third-party chatter.
```

### And one for you

Decide this week which migrations, template changes and large content prunes
can wait until the December update has finished, and tell the team the freeze
starts when Google posts the rollout date.
